# The Honest Agent: site

The public site for `honest-agent`: the landing page at `/`, built with Astro
from mockups made in Claude Design (the "First Screen Mockups" canvas, the source of
truth for the page's design), and the docs at `/docs/`, built with Starlight.

```sh
npm install
npm run dev      # http://localhost:4321
npm run build    # static site in dist/
```

## Layout

- `src/pages/index.astro`: the page, sections in handoff order.
- `src/components/sections/`: one component per mockup section
  (Hero, Connect, Loop, Define, Run, Review, Improve, Footer).
- `src/layouts/Base.astro`: `<head>`, the design-system styles, and two
  page-wide behaviours (see below).
- `src/content/docs/docs/`: the docs pages, in Markdown, served at `/docs/...`.
  Starlight's config (sidebar, theme) is in `astro.config.mjs`;
  `src/styles/docs.css` maps its colours and fonts to the design system tokens.
- `public/assets/`: the robot, the report screenshots, and
  `hero-poster.jpg`, the hero video's first frame (shown before it plays and when
  "reduce motion" is on).

## The hero video

The video is too big to keep in git, so it's served from Cloudflare R2: the bucket
`honest-agent-media`, at `https://media.thehonestagent.dev/hero.mp4`. It's silent, and
autoplays muted and loops. The local copy is in `media/` (ignored by git).

Browsers may keep it for a year (`immutable`), so never overwrite it under the same name.
To replace it, upload the new cut under a new name,
then change `src` in `src/components/sections/Hero.astro` and update the poster:

```sh
npx wrangler r2 object put honest-agent-media/hero-v2.mp4 --file media/hero-v2.mp4 \
  --content-type video/mp4 --cache-control "public, max-age=31536000, immutable" --remote
```


## Search engines and AI assistants

- `public/robots.txt` allows every crawler, and names the AI ones (OpenAI, Anthropic,
  Perplexity, Google-Extended, Bing) so a stricter default elsewhere doesn't win. Cloudflare's
  AI Crawl Control and managed robots.txt can still block them at the edge: keep AI crawlers
  allowed and managed robots.txt off in the dashboard.
- `Base.astro` sets the landing page's canonical URL, Open Graph tags and JSON-LD
  (`SoftwareApplication`, `WebSite`). Starlight does the canonical and Open Graph tags for the docs.
- `public/assets/og.png` (1200×630) is the share image for link cards and search result
  thumbnails, on the landing page and the docs. Its source is the "Share image A" artboard in
  the Claude Design project "First Screen Mockups"; keep the mascot and headline in the middle,
  because small thumbnails crop it to a square.
- `starlight-llms-txt` (in `astro.config.mjs`) writes `/llms.txt`, `/llms-full.txt` and
  `/llms-small.txt` from the docs.

## Reference pages

`src/content/docs/docs/reference/` is generated by `scripts/generate_reference.py` from
the CLI itself: every command and option from its Click definitions, and every config
setting from `config_file.py`. Run it after changing a command, an option or a setting,
from the repository root:

```sh
uv run --directory cli python ../site/scripts/generate_reference.py
```

CI regenerates the pages and fails if they changed. This is the one part of the site that
depends on `cli/`; a site in its own repo would install honest-agent to run it.

## Design system

The site uses the report's design system in `../ui/src/ds/`, through the `@ds`
alias (`astro.config.mjs` and `tsconfig.json`); nothing else outside `site/`
is imported. Don't edit it from here: `ui/src/ds/README.md` says how it syncs
with Claude Design. The landing page imports all of it (`@ds/styles.css`); the
docs import only the token files, because its `base.css` restyles `html`,
`body` and links, which would fight Starlight's own styles. `Logo` defaults to
`assets/logo-mark.png`, so the site passes `markSrc="/assets/robot.png"`.

To move the site into its own repo, copy the design system in and point the
alias at the copy.

## How the sections were built

Each section's markup and CSS come from its mockup almost unchanged, so the
page matches the reviewed designs in spacing, sizes and copy. The changes:

- Ids and keyframe names have a per-section prefix (`cn-`, `lp-`, `df-`,
  `rn-`, `rv-`, `im-`), because the mockups were separate pages and reused
  names like `c1` and `tyIn`.
- Colours and fonts that exactly match a design-system token use the token
  (`var(--fg-1)`, `var(--font-display)`, …). Mockup-only colours stay literal.
- The fonts are the design system's bundled files; only Lato (for the Slack
  windows) loads from Google Fonts.
- The nav and footer logos use the design system's `Logo`, rendered to static
  HTML. No React reaches the browser.
- Interactivity is still CSS only (hidden radios, `:checked ~`, `:has()`). The
  only scripts start animations when a section scrolls into view, and power
  the footer's copy button.

`Base.astro` resets `box-sizing` to `content-box` inside the sections, because
the mockup CSS was written for the browser default and the design system's `tokens/base.css`
sets `border-box` on everything.

Fixes from the handoff's "inconsistencies" list: `order_total_2026` is "Order
total in 2026" with `35055813985.22` everywhere; `expected_sources` is
`[lineitem, warehouse.main.orders]` on both Loop and Define; the loop's run id
matches the Run section.

The sample evals use current dates instead of the handoff's 1990s ones:
`revenue_q4` ("Revenue in Q4 2026") and `order_total_2026`. Every report
screenshot was regenerated to match, including the Define ones, which now use
the same data as the rest of the page (`llm_judge` shows `top_nations_last_year`).
See `scripts/report-screenshots/README.md` to regenerate them.

## Still open

- "See a report" (the hero's second button) and "Explore a real report" (Review section)
  link to `#see-a-report` for now: they will open the real report UI,
  built from runs of `init --example`, at `/report/`.
- Hosting: the site's address is `https://thehonestagent.dev` (the domain is on
  Cloudflare), set as `site` in `astro.config.mjs`. Cloudflare Pages deploys it from
  the `live` branch, which points at the latest release, and deploys `main` as a
  preview; CI only builds it (`.github/workflows/site.yml`). See "How changes reach
  people" in the repository's
  [CONTRIBUTING.md](https://github.com/jlcoto/the_honest_agent/blob/main/CONTRIBUTING.md).
- Asset paths are root-relative (`/assets/...`). If the site is hosted under a
  sub-path (e.g. a GitHub Pages project site), set `base` in
  `astro.config.mjs` and prefix the paths.
